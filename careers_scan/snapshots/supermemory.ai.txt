The path to useful AI is to scale in-context continuous learning that works with any model, any harness , and for all the varieties of use cases. As open-source model adoption grows and the world becomes even more multi-model , learning and memory should be separated from the model providers and be highly interoperable (hence in-context!).
Intelligence is no longer a constraint.
Pre-training and post-training, scaling on data and compute, will continue to push models’ intelligence, but will not enable them to learn and improve in real time.
We build all the hard infrastructure parts of a scalable memory system, with dense, interconnected, growing learnings , and an understanding of time.
Our model learner-1 helps any model continuously improve by extracting and dreaming on the context of any user, task, or tenant, and putting it on our vector-graph database. This is then brought to the model by injecting tokens into its context in real time.

Questions
What is supermemory?
supermemory is a memory API for AI agents and apps. It gives any model long-term memory: it extracts memories from conversations, documents and files, keeps a profile for each user, and brings the right context back when the model needs it. It is available as an API with TypeScript and Python SDKs, as plugins for coding agents, and as an MCP server.
How is agent memory different from RAG or a vector database?
A vector database stores embeddings and returns the nearest ones; what to store, update and delete is left to you. supermemory manages the memories themselves: it extracts facts, updates them when they change, forgets what has expired and keeps a profile for each user. It also does retrieval over your documents (SuperRAG), so there is no vector database to run.
Which models, agents and frameworks does supermemory work with?
Any model. There are SDKs for TypeScript and Python and a REST API; plugins for Claude Code, Cursor, Codex, OpenCode, OpenClaw and Hermes; an MCP server for Claude, ChatGPT and other MCP clients; and integrations for the Vercel AI SDK, LangChain, LangGraph, CrewAI, the OpenAI SDK, Mastra, Pipecat, LiveKit, Zapier and n8n.
Can I self-host supermemory?
Yes. supermemory local is a free self-hosted binary for up to 10,000 stored documents; it runs on your machine and is not open source. Running supermemory in your own cloud or on a dedicated instance is available on Scale and Enterprise, and Enterprise also supports fully air-gapped deployments, where LLM inference may be the only outbound call, or none at all.
Is supermemory open source?
Partly. The main GitHub repository, including the MCP server, and the plugins are MIT, and the TypeScript and Python SDKs are Apache 2.0. The memory engine is not open source: it runs in our cloud, as the free supermemory local binary, or in your own infrastructure on Scale and Enterprise.
